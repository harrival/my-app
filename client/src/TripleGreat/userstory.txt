Harmonized System Specification
Item Reservation Engine & Supervisor Control Panel
Technical Architecture & System Overview
________________


1. System Architecture & Harmonized Domain Model
This document specifies the unified architecture connecting the public customer booking experience with the internal supervisor administration portal. Every configuration made in the supervisor portal—inventory adjustments, calendar blackouts, content modifications, and policy overrides—directly drives and updates the public reservation engine in real time.
Core Synchronizations
* Inventory & Blackouts: Customer availability calculations dynamically combine physical inventory counts, active reservations, unexpired checkout holds, and supervisor-defined date blackouts.
* Reservation Lifecycle & Policy Overrides: Customer self-service cancellations and reschedules adhere strictly to the automated 7-day policy (100% refund prior to 7 days, 25% fee retained within 7 days). Supervisors possess role-based override capabilities to waive fees or manually adjust schedules.
* Content Management System (CMS) & Public Sync: Supervisor updates to announcements, vision and mission statements, blog posts, and photo/video media invalidate the application edge cache and immediately update the public booking interface.

Scenario: Date-range availability query with blackout enforcement
Given an item with a configured pool of identical units
When a customer selects a start and end date range
Then the system checks overlapping confirmed reservations, active checkout holds, and supervisor blackouts
And displays the exact remaining unit count for that window
And disables date selection if any date in the range is blacked out or fully booked.


Scenario: Temporary inventory reservation hold
Given available inventory for the selected date range
When the customer proceeds to checkout
Then the system places an atomic 10-minute hold on one inventory unit
And decrements visible availability for subsequent shoppers searching overlapping dates
And starts an on-screen expiration countdown timer.


Scenario: Checkout authentication choice (Guest vs. Account)
Given an active reservation hold
When the customer reaches the checkout view
Then the system presents two options: "Checkout as Guest" and "Sign In / Create Account"
And guest checkout requires only contact information, phone, and payment details
And account creation allows setting credentials and associates the booking to the customer profile.


Scenario: Automated free cancellation (>= 7 days prior)
Given a confirmed customer reservation with start date T_start
When the customer requests cancellation at timestamp T_cancel >= T_start - 7 days (168 hours)
Then the system issues a 100% refund of the original transaction amount
And updates the reservation status to CANCELLED
And immediately restores unit availability to the general pool.


Scenario: Automated late cancellation (< 7 days prior)
Given a confirmed customer reservation with start date T_start
When the customer requests cancellation at timestamp T_cancel < T_start - 7 days
Then the system retains 25% of the original charged fee as a cancellation fee
And issues an automated partial refund of 75% to the original payment method
And marks the reservation CANCELLED and restores unit availability.


Scenario: Policy-driven self-service rescheduling
Given a confirmed customer reservation
When the customer selects an alternate available date range
Then if requested >= 7 days before original start date, the schedule updates with no fee
And if requested < 7 days before original start date, the system charges a 25% modification fee before confirming the new dates.

4. Harmonized Data Schema & System State Machine
Unified Data Entities
* items: Catalog metadata, default daily rate, and deposit requirements.
* item_units: Physical serialized units linked to items with active status.
* reservations: Date range (daterange), unit assignment, customer contact/user reference, and lifecycle state (HOLD, CONFIRMED, CANCELLED, RESCHEDULED).
* inventory_blackouts: Administrative blackout date ranges preventing reservations.
* cms_content / cms_posts / cms_media: Dynamic marketing and operational content displayed across public pages.
* supervisor_audit_logs: Administrative action log recording overrides, fee waivers, and setting changes.
Reservation Lifecycle Dynamics
State
	Transition Trigger
	Timeout / Validation
	System Actions & Effects
	HOLD
	Customer initiates checkout
	10-Minute Redis TTL Expiration
	Locks unit availability; decrements available pool count; displays countdown timer.
	CONFIRMED
	Payment webhook or Supervisor creation
	Instant verification
	Persists reservation permanently; marks unit unavailable for selected date range.
	CANCELLED
	Customer self-service or Supervisor override
	Policy rule check (T-7 Days)
	Reclaims unit; calculates refund (100% or 75% unless waived); invalidates holds.
	RESCHEDULED
	Customer change or Supervisor override
	Availability check for new range
	Re-evaluates overlaps; applies 25% change fee if <7 days (unless waived by Supervisor).

5. Verification Checklist & Guardrails
* Database Integrity: PostgreSQL GIST exclusion constraints prevent overlapping active reservations for the same unit.
* Blackout Priority: Blackout ranges instantly invalidate availability and block concurrent holds.
* Financial Precision: All fee and refund calculations are executed in integer cents:
   * cancellation_fee_cents = round(original_amount_cents * 0.25)
   * refund_amount_cents = original_amount_cents - cancellation_fee_cents
* Role Protection: All /api/admin/* endpoints strictly enforce supervisor authorization at the gateway and middleware layers.
* Cache Consistency: Every supervisor update publishes a cache-bust event to ensure immediate visibility on the customer booking page.
